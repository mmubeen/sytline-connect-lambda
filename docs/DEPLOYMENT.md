# Deploying with the SAM CLI

Target: AWS GovCloud **us-gov-east-1**, one stack named `sytline-connect`, one configuration (`default`).
Everything below is run from the `scr/` directory. This guide covers deploying the code; the network and ERP
prerequisites are listed in section 2 and come from
`docs/Instruction Sheet AWS GovCloud API Gateway to On-Premises Sy.docx`.

> **Status:** the template builds and validates locally, but it has not yet been deployed to a real account.
> The SyteLine web-service names (collections, methods, SOAP operations) are unconfirmed until the read-only
> discovery task (T013 in `specs/001-syteline-erp-integration/tasks.md`) has run. **Keep live ERP writes off.**

## 1. What gets deployed

| Resource | Purpose |
|---|---|
| `OrderApi` (private REST API, stage `prod`) | `POST /confirmed-orders`, `GET /upload-jobs/{id}`; IAM auth; callable only through the approved `execute-api` VPC endpoint |
| `IntakeFunction` | validates and records an order, starts the worker, returns an upload ID |
| `StatusFunction` | returns the state of an upload |
| `WorkerFunction` (in your VPC, reserved concurrency 1, no automatic retries) | runs the upload against the SyteLine web service |
| `SweeperFunction` (every 5 minutes) | re-drives `accepted` uploads, parks stale `running` ones as `needs_reconciliation` |
| `DirectFunction` (in your VPC) | direct-invoke actions: `health`, `add_note`, `get_notes` |
| `DepsLayer` (`sytline-connect-deps`) | zeep, lxml, requests, urllib3 built for Linux x86_64 / Python 3.13 |
| `JobsTable` (DynamoDB, on demand, point-in-time recovery, TTL) | uploads and the `request_ref` index |
| DynamoDB gateway endpoint, Secrets Manager interface endpoint | so the worker in private subnets can reach them (optional, see `CREATE_VPC_ENDPOINTS`) |
| IAM roles | one per function, least privilege (generated by SAM) |

## 2. Prerequisites

**Tools (on the machine that deploys)**
- AWS CLI v2 with credentials for the GovCloud account (`AWS_PROFILE=<profile>`; the `aws-us-gov` partition).
- SAM CLI (`sam --version`): <https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html>
  or `pip install aws-sam-cli`.
- `python3` with `pip` (any recent 3.x) and `make`. **Docker and a local Python 3.13 are not needed**: `scr/Makefile`
  installs Linux wheels with pip's cross-platform flags.
- IAM permissions to create CloudFormation stacks, Lambda, API Gateway, DynamoDB, IAM roles, VPC endpoints and
  an S3 bucket for artifacts (SAM creates and manages that bucket: `resolve_s3 = true`).

**In the account (created before the first deploy)**
1. **Secret.** A Secrets Manager secret in us-gov-east-1 containing JSON with `SYTELINE_PASS`:
   ```
   printf '{"SYTELINE_PASS":"<password>"}' > /tmp/sytline-secret.json   # do not commit; delete afterwards
   aws secretsmanager create-secret --region us-gov-east-1 --name sytline/connect \
       --secret-string file:///tmp/sytline-secret.json
   shred -u /tmp/sytline-secret.json 2>/dev/null || rm -P /tmp/sytline-secret.json
   ```
   Note the ARN it prints (`arn:aws-us-gov:secretsmanager:us-gov-east-1:...`).
2. **API client path.** An `execute-api` **interface VPC endpoint** in the VPC the approved callers use; note its ID
   (`vpce-...`). The stack restricts the API to this endpoint.
3. **Worker network.** Private subnets (and their route tables) with a route to the plant over the Site-to-Site VPN,
   plus a security group that allows outbound **HTTP port 80** to the SyteLine web service and HTTPS to the AWS
   endpoints. Plant DNS must resolve the SyteLine host from these subnets. The Palo Alto side (IKE/IPsec, routes,
   policy, return path) is outside this repo; see the instruction sheet, section 2.
4. **Account limits.** Reserved concurrency of 1 for the worker needs at least 100 unreserved Lambda concurrency left
   in the account.

## 3. Configure

`scr/samconfig.toml` holds only the fixed settings (stack name, region, capabilities). Site-specific values live in
`scr/deploy.env`, which is git-ignored and contains no passwords:

```
cp deploy.env.example deploy.env
```

| Variable (`deploy.env`) | Template parameter | Meaning |
|---|---|---|
| `SYTELINE_WSDL` | `SytelineWsdl` | `http://<host>/IDORequestService/IDOWebService.asmx?wsdl` (HTTP, port 80) |
| `SYTELINE_USER` | `SytelineUser` | web-service user name |
| `SYTELINE_SECRET_ARN` | `SytelineSecretArn` | the secret from step 2.1 |
| `SYTELINE_CONFIG` | `SytelineConfig` | SyteLine configuration, default `CCT` |
| `SYTELINE_DEFAULT_WHSE`, `SYTELINE_DEFAULT_ORDTYPE` | `DefaultWhse`, `DefaultOrdType` | used when an order omits them |
| `API_VPCE_ID` | `ApiVpcEndpointId` | `execute-api` interface endpoint |
| `WORKER_VPC_ID` | `WorkerVpcId` | VPC of the worker subnets |
| `WORKER_SUBNET_IDS`, `WORKER_SG_IDS`, `WORKER_ROUTE_TABLE_IDS` | `WorkerSubnetIds`, `WorkerSecurityGroupIds`, `WorkerRouteTableIds` | comma-separated |
| `CREATE_VPC_ENDPOINTS` | `CreateVpcEndpoints` | `false` if the VPC already reaches DynamoDB and Secrets Manager (endpoints or NAT) |
| `LIVE_WRITES`, `LIVE_APPROVAL_REF` | `LiveWrites` | leave `false`; see section 7 |

## 4. Validate, build, deploy

```
export AWS_PROFILE=<govcloud-profile>
./deploy.sh --validate     # sam validate --lint
./deploy.sh --build        # sam build -> .aws-sam/build (layer + 5 functions)
./deploy.sh                # build + sam deploy, with an interactive change-set review
```

`deploy.sh` stops with a clear message if `deploy.env` is missing or any required value is empty. Equivalent raw
commands: `sam validate --lint`, `sam build`, `sam deploy --parameter-overrides 'Key="value"' ...` (quote every value;
list parameters such as subnets are comma-separated inside the quotes).

Review the change set before confirming. On the first deploy expect: the layer, table, API, five functions, and (if
enabled) two VPC endpoints. Later deploys change only what differs.

## 5. Verify after deploying

Stack outputs (API id, function names, table name):
```
aws cloudformation describe-stacks --region us-gov-east-1 --stack-name sytline-connect \
    --query 'Stacks[0].Outputs' --output table
```

1. **Dry-run health check** (no credentials, no login; proves the code loads and the web-service host is reachable):
   ```
   aws lambda invoke --region us-gov-east-1 --function-name <DirectFunctionName> \
       --payload '{"action":"health","dry_run":true}' --cli-binary-format raw-in-base64-out out.json && cat out.json
   ```
   Expected stages: `load`, `dns`, `tcp`, `wsdl`. A failing stage names where connectivity breaks (DNS, routing, security group, VPN).
2. **Full health check** (logs in with the secret): same call with `'{"action":"health"}'`; expected stages `dns`, `tcp`, `wsdl`, `token`.
3. **API from an approved client** (inside the VPC that has the `execute-api` endpoint, with IAM credentials):
   ```
   awscurl --service execute-api --region us-gov-east-1 -X POST \
       -H 'Content-Type: application/json' -d @order.json \
       https://<ApiId>-<API_VPCE_ID>.execute-api.us-gov-east-1.amazonaws.com/prod/confirmed-orders
   ```
   (request body: `specs/001-syteline-erp-integration/contracts/api.md`). Expect HTTP 202 and an `upload_id`; then
   `GET .../prod/upload-jobs/<upload_id>`. From outside the approved endpoint or without IAM credentials the call must be denied.
4. **Expected outcome while live writes are off:** the upload ends `failed` with code `LIVE_WRITES_DISABLED`, after
   the read-only customer lookup and **before** any number is allocated or any row is written. If the lookup itself
   fails (for example `ERP_UNREACHABLE`), the unconfirmed web-service names in `scr/syteline/idos.py` are the first
   thing to check. That is what the discovery task is for.

Logs: `sam logs --stack-name sytline-connect --region us-gov-east-1 --name WorkerFunction --tail`
(also `IntakeFunction`, `StatusFunction`, `SweeperFunction`, `DirectFunction`). Each request writes one structured line
(type, identifiers, outcome, duration). Passwords and tokens are never logged.

## 6. Updating

Change code or `deploy.env`, then run `./deploy.sh` again. SAM rebuilds, shows the change set and updates the stack.
Uploads already stored are kept; the table is not replaced by code changes.

## 7. Enabling live ERP writes (only for an approved test)

There is no test SyteLine. Live writes (number allocation, inserts, note creation) are off by default and must only be
enabled for a test the ERP owner approved in writing, with a reconciliation and cleanup plan
(`docs/reconciliation-runbook.md`; `specs/001-syteline-erp-integration/quickstart.md` step 5).

1. In `deploy.env` set `LIVE_WRITES=true` **and** `LIVE_APPROVAL_REF=<the approval reference>`. `deploy.sh` refuses
   `LIVE_WRITES=true` without a reference.
2. `./deploy.sh`; run the single approved test.
3. Set `LIVE_WRITES=false` (and clear the reference), `./deploy.sh` again, and confirm with a new upload that it ends
   `LIVE_WRITES_DISABLED`.

## 8. Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| `sam build` fails in `pip install` | pip too old for `--platform`: `python3 -m pip install --upgrade pip`; or no network access to the package index |
| `deploy.sh`: "missing in deploy.env" | fill in the named values |
| Stack in `ROLLBACK_COMPLETE` after a failed first deploy | `sam delete --stack-name sytline-connect --region us-gov-east-1`, fix the cause, redeploy |
| VPC endpoint creation fails ("private DNS already enabled" or a conflict) | the VPC already has one: set `CREATE_VPC_ENDPOINTS=false` |
| Worker times out reaching DynamoDB or Secrets Manager | no endpoint or NAT path from the worker subnets: enable `CREATE_VPC_ENDPOINTS` or add a NAT route; check the security group allows HTTPS out |
| `health` fails at `dns` or `tcp` | plant DNS not resolvable from the worker subnets, VPN route missing, or the security group blocks outbound port 80 |
| `health` fails at `token` | wrong user, or wrong password in the secret; check the secret JSON key is `SYTELINE_PASS` |
| Deploy fails on reserved concurrency | account has under 100 unreserved concurrency: request a limit increase or lower other reservations |
| API call returns 403 | not coming through the approved VPC endpoint, or missing/incorrect IAM credentials |
| Upload ends `LIVE_WRITES_DISABLED` | expected until an approved live test (section 7) |
| Upload ends `needs_reconciliation` | follow `docs/reconciliation-runbook.md`; never resubmit the same order until its records are reconciled |

## 9. Removing the stack

```
sam delete --stack-name sytline-connect --region us-gov-east-1
```
**This deletes the job table and every stored upload record** (point-in-time recovery is deleted with it). Export anything
you need first. The Secrets Manager secret is not part of the stack and is not deleted.
