# Tasks: SQL Server Calls for Numbers and Customer Lookup

**Input**: Design documents from `/specs/005-sql-server-calls/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/interfaces.md, quickstart.md

**Tests**: Included (plan.md specifies a recording fake database, a golden customer-match set, route and template tests). No real database, ERP or deployment from this environment.

**Organization**: Grouped by user story. Paths are relative to the repo root. Existing behaviour must not change when an operation's web-service endpoint is configured or its setting is absent (research.md R2): run `python -m pytest tests -q` after each phase and compare with the failures that already exist (12 failures and 2 errors in `tests/unit/test_transport.py` and `tests/contract/test_health.py`).

**Hard rules**: the driver is imported in `src/syteline/sqlserver.py` only; its statements are exactly the five in data-model.md ("Statement whitelist"), all values passed as parameters, the routine name taken from a two-entry constant; by default the connection is encrypted with the certificate chain verified and `SQL_CA_PEM` required; an unencrypted connection exists only behind the explicit `SYTELINE_SQL_ENCRYPT=false` setting (warned on every connection; Phase 8) and is never reached by fallback; the route is decided from settings alone and never switched after a failure; the password and login never appear in logs, errors or responses; numbering is refused unless live writes are enabled; an unknown number outcome is `UNCERTAIN_OUTCOME` and is never retried.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: US1 = reserve numbers through the database (P1), US2 = find the customer through the database (P1), US3 = customer defaults (P2), US4 = connectivity check (P3)
